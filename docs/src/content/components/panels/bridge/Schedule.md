# Schedule

予定を、矢羽根 (@yanqirenshi/d3.yabane) で並べます。(0.4.0 以降)
艦橋 (`/`) の「Schedule」タブのパネルです。
WBS とプロジェクトの行には、マイルストーンを △ で描けます。(0.10.0 以降。下の「マイルストーン」)
矢羽根・WBS の箱・プロジェクトの箱・マイルストーンを Ctrl + クリック (Mac は ⌘ + クリック) すると、インスペクタで書き換えられます。(0.9.0 以降。マイルストーンは 0.10.0 以降。下の「Ctrl + クリックで書き換える」。0.10.x までは右クリックで、0.8.x までは、見るだけの図でした)

- ソース: `packages/ihub.core/src/components/panels/bridge/components/Schedule.js`

## 予定のデータ

予定は、WBS (`data/wbs/`) とは切り離して、`data/master_schedule/` のファイルに書きます。(0.7.0 以降。0.8.0 で 3 つのファイルにし、0.10.0 で `milestones.json` を足しました)
ファイルの形は、d3.yabane の入力と同じです。(d3.yabane のショーケースのファイルを、そのまま置けます)

| ファイル | 中身 |
|---|---|
| `data/master_schedule/projects.json` | プロジェクト。いちばん左の列に描きます。(任意) |
| `data/master_schedule/wbs.json` | WBS (行)。プロジェクトの右に、入れ子の列で並びます。 |
| `data/master_schedule/workpackages.json` | ワークパッケージ。矢羽根になります。 |
| `data/master_schedule/milestones.json` | マイルストーン。WBS かプロジェクトの行に、△ で描きます。(任意。0.10.0 以降) |

書き方は、[データの管理](#/data) の「Schedule の予定 (`master_schedule`)」にあります。

- どのファイルも、無くても動きます。
- ワークパッケージも、描けるマイルストーンも無いときは、図の代わりに、書き方の知らせを出します。(0.9.x までは、ワークパッケージが無いとき)
- 0.6.x までの、`data/wbs/workpackages.json` の `plan` は、0.7.0 で使えなくなりました。(書いてあると、`ihub-srv check` が誤りにします)

## 図の描き方

1. プロジェクトを、いちばん左の列に描きます。
2. WBS は、プロジェクトの右に、入れ子 (`parent`) の深さごとの列に描きます。
3. ワークパッケージは、親 (`parent` の WBS か、`project` のプロジェクト) の行に、矢羽根で描きます。
4. 同じ箱の中で、期間が重なる矢羽根は、重ならない段に分けて描きます。(0.5.0 以降)
5. マイルストーンは、親 (`parent` の WBS か、`project` のプロジェクト) の行の中の、日付の位置に、△ と名前で描きます。(0.10.0 以降。下の「マイルストーン」)

並びは、次のとおりです。

- プロジェクトは `projects.json` の順、WBS は `wbs.json` の順 (同じ親の下で) に、上から並びます。
- 子の WBS を持つ箱の直下のワークパッケージは、子の WBS のあとに、開始日の順で並びます。
- 予定の無い WBS も出ます。

名前の列は、次のように描きます。(0.8.1 以降。d3.yabane 0.5.0)

- 列 (深さ) ごとの幅は、その列の名前が収まる幅になります。(名前が短ければ細く、長ければ太くなり、時間軸の始まる位置も変わります)
- 名前は、省略せずに出します。
  ただし、全角 30 文字ぶん (全角 1・半角 0.55 として数える) を超える名前だけ、末尾を `…` にします。
- 子の WBS を持たない箱は、右端の列まで伸びます。

表示する期間は、予定の一番早い `from` から、一番遅い `to` までです。
マイルストーンの `date` が、それより早いか遅いときは、その日まで広げます。(0.10.0 以降)
前後に 1 目盛りずつの余白を付け、サイクルの初めと終わりにそろえます。
目盛りの数が少ないときは、右へ延ばします。(最小は、日 28・週 15・月 12)

行の区切り線 (横の線。色は `#aaa`) は、次のように引きます。

- 最上位の箱 (プロジェクト、または最上位の WBS) どうしの間に、図の左端から時間軸の右端まで引きます。
- 入れ子の子どうし (子の WBS・親の箱の直下のワークパッケージの帯) の間にも、間の真ん中の高さに、親の箱の右端から時間軸の右端まで引きます。(0.9.0 以降。d3.yabane 0.7.0。0.8.x までは、最上位の箱どうしの間だけでした)
- 同じ帯の中の段 (期間が重なって、下へ積んだ矢羽根) の間には、引きません。
- 入れ子の無いデータは、0.8.x と同じ見え方です。

今日の位置には、現在線 (縦の線) を描きます。
今日が表示する期間の外のときは、描きません。(0.8.2 以降。d3.yabane 0.6.0。0.8.1 までは、時間軸の外に描いていました)

## マイルストーン

0.10.0 以降の動きです。(d3.yabane 0.9.0)
`data/master_schedule/milestones.json` に書いたマイルストーンを、WBS かプロジェクトの行の中の、`date` の位置に、△ と名前で描きます。
△ の頂点が、その日の位置に来ます。
書き方は、[データの管理](#/data) の「Schedule の予定 (`master_schedule`)」にあります。

- 置く行の決め方は、ワークパッケージと同じです。(`parent` があれば、その WBS の行。無ければ、`project` のプロジェクトの行)
- 同じ行の中では、日付の順に並びます。
  矢羽根やほかのマイルストーンと横に重なるときは、下の段に積みます。(「△ + 名前」の幅で、重なりを見ます)
- ワークパッケージの期間の外の日付も、描きます。(表示する期間が広がります)
- `date` が実在しない日のものと、置く行が見つからないものは、描きません。(`ihub-srv check` が誤りとして知らせます)
- △ を押しても、何も起きません。(行き先は持ちません)
  Ctrl + クリック (Mac は ⌘ + クリック) すると、インスペクタが出ます。
- `milestones.json` が無いときは、マイルストーンの無い図を描きます。(0.9.x と同じ図)

## 図でできること

| 操作 | 内容 |
|---|---|
| 「日・週・月」のボタン (図の右上) | 時間の目盛りのサイクルを切り替えます。(0.7.0 以降。初めは週) |
| 「−」「＋」のボタン (「日・週・月」の左) | 1 目盛りの幅を、`50%`・`75%`・`100%`・`150%`・`200%`・`300%`・`400%` の 7 段で変えます。ボタンの間に、今の段を出します。(0.8.1 以降。初めは 100%) |
| 矢羽根を押す (修飾キーなし) | ワークパッケージの行き先へ移ります。(`wbs` を書いたときは `/wbs/{id}` へ移り、`url` を書いたときは新しいタブで開きます。どちらも書かないときは、何も起きません) |
| マイルストーンの △ を押す | 何も起きません。(0.10.0 以降) |
| 矢羽根・WBS の箱・プロジェクトの箱・マイルストーンを Ctrl + クリック (Mac は ⌘ + クリック) | 右端にインスペクタを出して、書き換えられます。矢羽根でも、行き先へは移りません。(0.9.0 以降。マイルストーンは 0.10.0 以降。0.10.x までは右クリック。下の「Ctrl + クリックで書き換える」) |
| ホイール・ドラッグ | 拡大・縮小し、図全体を動かします。 |

- 目盛りの見出しは、日は日の数字、週は週の初めの日 (`11/1` など。日曜始まり)、月は `YYYY-MM` です。日・週では、月の見出しが、その上の段に出ます。
- 1 目盛りの幅を変えたときは、時間軸の横の長さだけが変わります。(表示する期間・行の高さ・名前の列の幅は、変わりません) 画面の中央にあった日付が、ほぼ中央に残るように、横の位置を合わせます。
- 100% より狭い段では、目盛りの見出しの文字を、幅に合わせて小さくします。(50% で半分の大きさ)

## Ctrl + クリックで書き換える

0.9.0 以降の動きです。
矢羽根 (ワークパッケージ)・WBS の箱・プロジェクトの箱・マイルストーンの △ と名前 (0.10.0 以降) を Ctrl + クリック (Mac は ⌘ + クリック) すると、コンテンツエリアの右端に、インスペクタが出ます。(0.11.0 以降。0.10.x までは、右クリックで開いていました)
作りは、[Overview](#/components/panels/bridge/Overview) と同じです。
箱は、名前の文字の上でも、塗りの内側のどこでも構いません。(入れ子の親の L 字の箱も同じです)
右クリックでは、インスペクタは開かず、ブラウザの普通のメニューが出ます。

| 押したもの | 書き換えるファイル | 出る項目 |
|---|---|---|
| プロジェクトの箱 | `master_schedule/projects.json` | 名称・ID (読むだけ)・見た目 |
| WBS の箱 | `master_schedule/wbs.json` | 名称・ID (読むだけ)・親の WBS・親のプロジェクト・見た目 |
| 矢羽根 | `master_schedule/workpackages.json` | 名称・ID (読むだけ)・親の WBS・親のプロジェクト・予定の開始日・予定の終了日・見た目 |
| マイルストーンの △ と名前 | `master_schedule/milestones.json` | 名称・ID (読むだけ)・親の WBS・親のプロジェクト・日付・見た目 (0.10.0 以降) |

- 親の WBS・親のプロジェクトは、読むだけです。(書いてあるときだけ出ます)
- 見た目は、背景色・枠線の色・枠線の太さ・枠線の種類・文字の大きさ・文字の色です。
  書いていない項目には、図に描いている値 (d3.yabane の既定) が出ます。
- 項目ごとの保存先と入れられる値は、[図の編集](#/diagrams) の「Schedule で名前・予定・見た目を変える」にあります。
- 「適用」で、変えた項目だけを、そのファイルに書きます。
  書いたあとは、図を作り直します。
  位置・拡大の度合い・サイクル・1 目盛りの幅は、変わりません。
  名前を変えたときは、名前の列の幅も、新しい名前に合います。
- 入力の誤りと、保存の失敗は、図の上に知らせます。(書きません)
- インスペクタを開いているあいだも、右上の「−」「＋」と「日・週・月」は、インスペクタの左に出て、押せます。
  切り替えても、インスペクタは開いたままです。
- ほかから (エディタ・git など) データが変わって、開いていたレコードが無くなったときは、インスペクタを閉じます。
- 矢羽根の、修飾キーの無いクリックは、これまでどおり、行き先へ移ります。
  Ctrl + クリックでは、行き先へは移らず、インスペクタが開きます。(0.11.0 以降)
  マイルストーンの △ の、修飾キーの無いクリックでは、何も起きません。

次のものは、インスペクタでは書き換えられません。
ファイルを直接直します。(インスペクタの「JSON」のタブで、レコード全体を見られます)

1. 親 (`parent`・`project`) の付け替え
2. 並び順 (ファイルの配列の順です)
3. レコードの追加と削除
4. 説明 (`description`)
5. 行き先 (`wbs`・`url`)
6. `result`・`progress`

## ブラウザに覚えるもの

次のものを、ブラウザの `localStorage` に覚えます。
人ごと・ブラウザごとの記憶で、`data/` は変わりません。

| 覚えるもの | 鍵 | 覚えたものが無いとき |
|---|---|---|
| サイクル | `ihub:{app.name}:schedule:cycle` | 週 |
| 1 目盛りの幅の段 (サイクルごと) | `ihub:{app.name}:schedule:width:{d\|w\|M}` | 100% |
| 図の位置と拡大の度合い (サイクルごと) | `ihub:{app.name}:view:schedule:{d\|w\|M}` | 図の全体が画面に収まる度合い |

- 図の code は、サイクルごとに `schedule:d`・`schedule:w`・`schedule:M` です。(0.7.0 以降。0.6.x までの `schedule` で覚えたものは、使いません)
- 幅の段ごとには、位置を分けて覚えません。

## import のしかた

```jsx
import { panels } from '@yanqirenshi/ihub.core';

// <panels.bridge.Schedule/>
```

## props

props はありません。
(タブのあるページのパネルとして使うと、`tab` を受け取りますが、使いません)

## 使い方の例

ほかのページのタブに、同じ図を出します。([ページのタブとパネルを足す](#/customize))

```jsx
import { panels } from '@yanqirenshi/ihub.core';

const config = {
    // (省略)
    tabs:   { PAGE_DESIGN: { list: [{ code: 'schedule', label: 'Schedule' }] } },
    panels: { PAGE_DESIGN: { schedule: panels.bridge.Schedule } },
};
```

艦橋の Schedule タブを出したくないときは、設定でタブを隠します。

```jsx
const config = {
    // (省略)
    tabs: { PAGE_BRIDGE: { list: [{ code: 'schedule', hidden: true }] } },
};
```

## 注意

- `<IHub>` の中で使ってください。
  次のものを使います。
  1. API サーバーから読み込んだ `master_schedule` のデータ
  2. react-router (`useNavigate()`。矢羽根を押したときに移るため)
  3. 設定の `app.name` (ブラウザに覚える鍵)
  4. 設定の `diagrams.schedule.grid` (グリッド線。既定では描きません。[カスタマイズ](#/customize) の「図のグリッド線」)
  5. API サーバーの `PATCH /api/master_schedule/{projects|wbs|workpackages|milestones}/{id}` (インスペクタの「適用」で書くため。0.9.0 以降。`milestones` は 0.10.0 以降)
- `@yanqirenshi/ihub.srv` も、同じ版にしてください。(`master_schedule` の形の検査は、ihub.srv にあります)
- インスペクタの項目・入力の検査・既定の見た目は、`@yanqirenshi/model.yabane` が決めます。(0.9.0 以降) インスペクタは、`@yanqirenshi/colonoscope` の `ModelInspector` です。
- 大きさは親の大きさ一杯 (`width: 100%`・`height: 100%`) です。
  親に高さを付けてください。
- 図は 1 つだけです。
  2 つの場所に出しても、同じ `data/master_schedule/` を描き、覚える位置も同じです。
